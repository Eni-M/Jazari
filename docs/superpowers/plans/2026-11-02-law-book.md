# Law Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jazari answers .NET questions from Microsoft's own docs when they hold the answer, shows the source, and sends nothing when they don't. It ships only if the test set score rises above 37/45.

**Architecture:** A one-off Python tool builds a read-only SQLite FTS5 file from Microsoft's docs at pinned commits. The gateway searches it for each plain question, decides in code whether a passage really covers the question, and puts at most 300 tokens inside the question's own message. Nothing is added to history, so the prompt's start stays cached.

**Tech Stack:** C#/.NET 10, `Microsoft.Data.Sqlite` (already a dependency), xUnit, Python 3.12 stdlib (`py -I`, `unittest`, `sqlite3`), PowerShell 5.1 for the updater.

**Spec:** `docs/superpowers/specs/2026-11-02-jazari-accuracy-design.md`, phase 4, with the correction in `reports/Local inference sources for Jazari.md`: decide "nothing relevant" from evidence, not a score threshold. Phase 4b (web lookup) is not in this plan.

## Global Constraints

- Sources, pinned: `dotnet/docs` at `40fbd4674d72503f18781f67dec0fa69315bb84a`, `dotnet/AspNetCore.Docs` at `9dfb3e392d31b33761e7cc5070ea4a7d92082907`, `dotnet/EntityFramework.Docs` at `b0c8daf21d4dd8157e9696e77942278b9722b226`. Text is CC-BY 4.0 and code MIT (checked 2026-11-02), so every answer that used a passage shows its source, and the download carries an attribution notice.
- Each question sends at most 300 tokens of passages. No second model, no embeddings, no new NuGet or Python dependencies.
- Anti-goal, from the spec: a test question must not leak into the law book's tuning. Tune retrieval only on `lawbook/dev_questions.json`, whose questions must not appear in or paraphrase `eval/questions.json`. Run the test set only at the gate. Don't open `eval/questions.json` while writing the dev set.
- Anti-goal: inventing things. If nothing covers the question, nothing is sent, and no `source` row appears.
- Never run the real Jazari app, `jazari update` or the installer from Claude Desktop. A temporary `llama-server` on 8099 and a temporary gateway on 5099 with a temp data folder are allowed. Stop them when done.
- Build and test with `--disable-build-servers`. Keep code that touches the registry or writes executables out of Jazari and its tests. Pass absolute paths to `--llama`.
- Time limits: plain question usually at most 30 s; first answer after `/read` at most about 2 minutes; follow-up at most 30 s.
- Budget is $0. Offline stays the default promise: Jazari works exactly as today with no law book file.
- Branch `feat/law-book` from `main`.

## Review Focus

1. A question that isn't about .NET ("hello", "what's for dinner"): nothing sent, no `source` row. Pinned in Task 2.
2. Missing or damaged `law-book.db`: Jazari answers as today, and says nothing alarming. Pinned in Task 2.
3. A question holding FTS5 syntax or symbols (`C#`, `"quoted"`, `foo*`, `AND`, `IQueryable<T>`): no crash, still searches. Pinned in Task 2.
4. A very long pasted question or stack trace: search stays fast and doesn't choke. Pinned in Task 2.
5. Docs covering old versions of the same feature: passages come from the latest version's text. Pinned in Task 1.

- [ ] **Step 3: Implement `LawBook.Search`**

Open read-only (`Mode=ReadOnly`), and catch `SqliteException` so any failure returns empty. The steps are the decision, so follow them in order:

1. **Terms:** the question's words from a Unicode word regex, lowercased, without the stopwords in `ConversationSearch` (make that list `internal`), first 32 distinct only. None: return empty.
2. **Search:** an FTS5 query of the terms, each double-quoted, joined by `OR`, `ORDER BY bm25(chunks, 5.0, 1.0)`, `LIMIT 20`. Title weighs 5.
3. **Named things:** tokens holding an inner capital or a dot (`FrobnicateAsync`, `Results.NotFound`, `IDisposable`) and versions (`.NET 8`, `C# 12`). A chunk must contain every one, ignoring case, or it's out.
4. **Uncovered word:** count each term's chunks with a `MATCH` per term, so FTS5's stemming applies. If a term is in no chunk at all and isn't a number, return empty.
5. **Coverage:** a chunk must contain at least half the terms, by `MATCH` on the term plus the chunk's rowid, and must contain the term with the lowest count from step 4. With one term, that term must be in the title.
6. **Take** chunks in rank order until 2 chunks or 300 tokens by `PromptBuilder.EstimateTokens`.

Add a comment naming why there's no score threshold: reame measured similarity at 0.895 for answerable questions and 0.879 for traps, so a threshold can't separate them.
